## 📖 本講重點精要

### 1. 什麼是 AI Agent？它與傳統生成式 AI 的根本差異

很多同學在接觸 AI 時，第一個聯想到的是 ChatGPT、Claude 或 Gemini 的網頁對話介面。但傳統聊天 AI 與真正的 **AI Agent（智慧代理人）** 有著本質上的跨越：

| 比較維度 | 傳統雲端對話 AI（Web Chat） | 本機 AI Agent（如 Claude Code, OpenCode, AntiGravity） |
|:---|:---|:---|
| **本質形象** | **動嘴的軍師**（只負責出主意、給文字） | **有手有腳的實習助理**（會思考、且能動手執行） |
| **運作邊界** | 封閉在瀏覽器分頁中，碰不到你的電腦 | 直接運行在你的電腦終端（Terminal / 本機環境） |
| **檔案處理** | 必須手動上傳檔案、等它產生後再手動下載 | 直接讀取本機資料夾，甚至自己建立/修改數十個檔案 |
| **執行力** | 只能生成程式碼，要求你「請手動複製去跑」 | 能自己開啟命令列跑程式、檢查報錯、自動修正 |
| **操作流程** | 人類是「搬運工人」（在各個視窗間複製貼上） | 人類是「專案經理」（出題目、審核結果、決定方向） |

> 💡 **核心金句**：  
> 傳統 AI 是「你問一句，它回一段」；AI Agent 則是「你給它一個目標，它自己拆解步驟、呼叫工具、執行到完成為止」。

---

### 2. 為什麼要「用 Agent 來學習 Agent」？

在過去，學習一項新的軟體工具或寫程式，初學者必須先記住一大堆指令、環境設定步驟、語法格式，常常還沒開始做事就因為環境報錯而放棄。

三師爸提出的核心心法是：**「不要自己當人肉編譯器，讓 Agent 當你的家教與助手！」**
- 你不需要先背下所有指令。
- 你可以直接把教學文件、規範清單、或範例 Repo 丟給 Agent。
- 指示它：「請研讀這份教學文件，幫我檢查我的電腦環境，並一步步引導我完成今日任務。」
- **學習典範轉移**：從「背誦知識」變成「具備精準描述問題與閱讀回報的能力」。

---

### 3. 工作流思維（Workflow）與「複製成熟大腦」

初學者最大的瓶頸往往是「不知道該如何開始下指令」或是「每次換新對話就要重新調教 AI 一遍」。

#### (1) 拒絕重複造輪子：GitHub 儲存庫的妙用
- 在開源社群中，已經有許多專家（如三師爸）將成熟的工作流程、提示詞工程、自動化工具打包成 GitHub Repository（儲存庫）。
- 透過一個 GitHub 連結，或者一組 Markdown 設定檔（如懶人包），Agent 能直接「讀懂」整套專家知識與執行標準，直接把整套工作流「安裝」在你的電腦中。

#### (2) 專案大腦的誕生：`AGENTS.md` 的前導概念
- 當我們在專案資料夾中放置一份給 Agent 閱讀的專案規格書（如 `AGENTS.md` 或 `CLAUDE.md`），Agent 一進入資料夾就會自動閱讀。
- 這樣一來，Agent 就能瞬間知道：
  - 這個專案要解決什麼問題？
  - 目前有哪些檔案與資料夾？
  - 有什麼限制（例如：一律使用繁體中文、不能隨意刪除舊檔案）？

## 🎯 學生課堂思考題（Q&A）

1. **問：我完全不會寫程式，也可以使用 AI Agent 嗎？**  
   *答*：絕對可以！Agent 本身就具備撰寫與執行程式碼的能力。你扮演的是「驗收者」與「需求提出者」。你只需要清楚告訴它你想要的輸入（如：這些成績單 Excel）與預期的輸出（如：算好的平均分與獎狀），程式執行的苦工交給 Agent。

2. **問：為什麼說使用 Agent 時，人類的責任反而變成了「專案經理」？**  
   *答*：因為 Agent 擁有了在你的電腦上讀寫檔案的權力，如果不小心下錯指令（如「刪除所有檔案」），它真的會執行。因此使用者需要具備清晰的邏輯、審核 Agent 計畫的判斷力，而不是一味盲目信任。

## 🛠️ 本單元學生實踐小任務

- [ ] **任務一**：在自己的電腦終端中，開啟 Agent（如 Claude Code / OpenCode / AntiGravity）。
- [ ] **任務二**：不手動點擊滑鼠，只用一句自然語言對話讓 Agent 回報目前專案資料夾裡有哪些檔案。
- [ ] **任務三**：請 Agent 建立一個名為 `hello_agent.txt` 的檔案，並在裡面寫上一句對未來的自我期許，確認本機資料夾中是否真的出現了該檔案。
